# TU Online

LMS Университета Ташенева: курсы с видео, тесты и задания со сроками, журнал с правилами «вовремя» и обмен оценками с Platonus. Три языка интерфейса (қазақша, русский, English), удобно с телефона, есть режим для слабовидящих.

Сделано по ТЗ «LMS Университета Ташенева (MVP до 31.12.2026)».

## Главный принцип

Platonus остаётся главным источником людей, групп, ИУП и итоговых оценок. TU Online отвечает за контент, прохождение курса и текущее оценивание и отдаёт оценки в Platonus только по правилам сроков.

## Что умеет

| Роль | Главный экран | Что ещё |
| --- | --- | --- |
| Студент | мои курсы, «Продолжить урок», сроки на неделю | урок с плеером и учётом просмотра, тест с таймером, сдача заданий, оценки и рейтинг допуска |
| Преподаватель | мои потоки, счётчик «на проверку», окна оценивания | журнал потока, проверка работ, заявки на позднюю оценку, подтверждение ведомости |
| Автор курса | мои курсы в работе, статус видео | конструктор с перетаскиванием, загрузка курса архивом, папка видео по именам, банк вопросов из Excel, копия курса |
| Заведующий кафедрой | готовность курсов кафедры | утверждение и публикация курсов, назначение авторов, успеваемость по потокам |
| Деканат | сводка факультета | отстающие, незакрытые ведомости, выгрузка в Excel |
| Учебная часть | готовность курсов по вузу | академический календарь и окна, схемы оценивания, шаблоны курсов, отчёт для лицензирования |
| Офис регистратора | обмен с Platonus | мастер импорта с проверкой по строкам, ведомости к отправке, заявки, история обменов, выдача паролей группам |
| Эдвайзер | прогресс своих групп | карточка студента (только просмотр) |
| Ректорат | один сводный дашборд | только просмотр |
| Администратор | пользователи и роли | интеграции (Bunny, Platonus), оргструктура, журнал действий |

Правила из раздела 5.3 ТЗ:

- у каждого элемента оценивания окно: открыт с → срок → жёсткое закрытие (из академического календаря);
- сдал после срока, но до закрытия — «поздно» и правило схемы (штраф в процентах или ноль);
- после закрытия окна или отправки ведомости оценку меняют только по заявке, которую одобряет регистратор; всё пишется в журнал;
- допуск к РК — обязательные уроки до недели РК пройдены, видео просмотрены не меньше чем на 90%;
- рейтинг допуска к экзамену: R1 = ТК1·w + РК1·(1−w), R2 = ТК2·w + РК2·(1−w), РД = (R1 + R2) / 2, порог настраивается;
- ведомость уходит пакетом: преподаватель подтверждает → регистратор проверяет и отправляет → после подтверждения Platonus оценки блокируются; итог с экзаменом считает Platonus.

## Демо

На бесплатном стенде включён демо-режим: на странице входа есть кнопки для каждой роли, пароль у всех `demo12345`.

## Стек

- Next.js 16 (App Router) + TypeScript, Tailwind CSS 4
- PostgreSQL 16+, Drizzle ORM, свои SQL-миграции в `drizzle/`
- next-intl: kk / ru / en, язык в cookie и в профиле
- pg-boss — фоновые задачи на той же PostgreSQL (без Redis)
- Bunny Stream — хранение, перекодирование, CDN и плеер; загрузка из браузера по tus с докачкой
- Файлы — в PostgreSQL (бесплатный стенд) или в S3/MinIO (свой сервер)

## Запуск локально

```bash
npm install
cp .env.example .env.local        # DATABASE_URL на локальную PostgreSQL
npm run db:migrate                # создать таблицы
npm run db:seed                   # демо-данные (на проде не запускать)
npm run dev                       # http://localhost:3000
```

Проверки: `npm run typecheck`, `npm test`, `npm run build`.

## Бесплатный стенд и переезд на свой сервер

Сейчас стенд работает бесплатно: приложение на Vercel, база — бесплатная PostgreSQL в Supabase. Это только для показа и пилота: по закону РК о персональных данных базу со студентами нужно держать на сервере в Казахстане. Код от этого не зависит — переезд описан в [docs/SERVER.md](docs/SERVER.md): `docker compose up -d` на сервере в РК, перенос базы одним дампом, смена DNS.

## Обмен с Platonus

Пока нет доступа к API — файлами Excel/CSV через «Офис регистратора → Импорт». Форматы и порядок загрузки — в [docs/PLATONUS.md](docs/PLATONUS.md). Код обмена написан один раз: когда появится API, задаются `PLATONUS_API_URL` и `PLATONUS_API_TOKEN`, меняется только транспорт (`src/lib/platonus/adapter.ts`).

## Загрузка курса в один клик

ZIP или папка с `course.xlsx` (или `course.csv`) и материалами. Строка таблицы — один блок:

```csv
module_no,week,module_title,lesson_no,lesson_title,block_no,block_type,block_title,file_or_text,required
1,1,Введение,1,Что такое ООП,1,video,Лекция 1,videos/OOP_M01_L01.mp4,yes
1,1,Введение,1,Что такое ООП,2,file,Конспект,files/OOP_M01_L01.pdf,no
1,1,Введение,1,Что такое ООП,3,quiz,Проверка,quizzes/OOP_M01_L01.xlsx,yes
```

Архив читается прямо в браузере (ZIP64, имена в UTF-8 и CP866), видео уходят в Bunny напрямую, сервер вуза гигабайты не принимает. Папку видео с именами `КОД_M01_L03.mp4` система раскладывает по модулям и урокам сама.

## Структура кода

```
src/
  app/            страницы по ролям: learn, teach, studio, department, faculty,
                  academic, registrar, advisor, overview, admin; api/ — файлы, видео, cron
  components/     интерфейс (ui — общие элементы, по папке на кабинет)
  db/schema.ts    47 таблиц из раздела 4 ТЗ (схема lms)
  i18n/dict/      все тексты интерфейса сразу на трёх языках
  jobs/           фоновые задачи (напоминания, просроченные тесты, видео)
  lib/rules/      правила ТЗ отдельными функциями с тестами
  lib/platonus/   форматы файлов, синхронизация, адаптеры файл/API
  server/         серверные действия (формы и кнопки)
drizzle/          SQL-миграции
scripts/          migrate, seed, worker (pg-boss), backup
tests/            тесты правил и разбора файлов
```

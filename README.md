# TU Courses — платформа онлайн-обучения Университета Ташенева

Информационная система для реализации образовательных программ высшего
образования с применением дистанционного обучения. Компонент информационной
системы управления образованием вуза (п. 61 Типовых правил деятельности ОВПО,
приказ МНВО РК № 595).

Реализованы этапы 1—7 технического задания v1.0.

**Стенд:** <https://tu-courses-kano6.vercel.app>
(тот же стенд доступен по адресу <https://tu-courses-one.vercel.app>; при входе
система приводит адрес к первому — сессия привязана к домену)

---

## Что это за продукт

Платформа ведёт полный цикл обучения по кредитной технологии: от утверждения
рабочего учебного плана по нормативам ГОСО до выдачи диплома с приложением.
Она рассчитана на четыре потока работы, идущих одновременно.

**Обучающийся** формирует индивидуальный учебный план из выборных дисциплин,
отправляет его эдвайзеру, после согласования регистрируется на конкретные
потоки, проходит курсы (лекции, тесты, задания с загрузкой файлов), видит свою
посещаемость и GPA, подаёт апелляцию на оценку, ведёт дневник практики,
переписывается в чатах группы и дисциплин.

**Преподаватель** собирает курс в конструкторе (модули, элементы содержания,
банк вопросов, тесты, задания), ведёт журнал посещаемости, выставляет оценки
рубежных контролей, проверяет работы, видит аналитику по курсу.

**Офис Регистратора и деканат** ведут контингент, группы, академический
календарь, окна регистрации, согласуют ИУП, закрывают ведомости, оформляют
перезачёт кредитов, распределяют на практику, назначают аттестационные
комиссии, оформляют протоколы защиты и дипломы.

**Методист и администратор** согласуют курсы и учебные планы, ведут справочники
и настройки, публикуют адресные объявления, читают журнал аудита и отчёты.

Нормативная рамка — ГОСО (приказ МНВО РК № 2) и Типовые правила деятельности
ОВПО (№ 595). Правила, которые нельзя нарушить, вынесены в проверяемые
предикаты: соответствие учебного плана ГОСО, объём кредитов в год, обязательные
дисциплины, продолжительность академического периода, условия диплома
с отличием, условия допуска к итоговой аттестации.

**Фирменный стиль.** Палитра выведена из логотипа Университета Ташенева:
основной тон `#E70426` (осветлён от логотипного `#F90428` до контраста 4.72:1 —
норма AA для текста), белый словесной части логотипа стал фоновым тоном
поверхностей. В тёмной теме основной тон заменяется на `#FF7A8A`: логотипный
красный на тёмном фоне не проходит по контрасту. Знак логотипа выводится
CSS-маской и красится текущим цветом, поэтому он одинаково читается в обеих
темах и в шапке, и на favicon.

## Быстрый старт

> **Запускаете впервые и ничего не устанавливали?**
> Пошаговая инструкция без локальной установки — `docs/QUICKSTART.md`:
> GitHub → Supabase → Vercel, всё в браузере, 30–45 минут.

Локальная разработка:

```bash
npm install
cp .env.example .env          # заполнить значения, см. docs/DEPLOY.md
npm run db:push               # схема
npm run db:rls                # закрыть таблицы от анонимного ключа Supabase
npm run db:seed               # справочники + демонстрационные данные
npm run db:seed:curriculum    # профили ГОСО + учебный план 6В01601
npm run db:seed:iep           # учебный год, группа, обучающиеся, окна регистрации
npm run dev
```

> **`db:rls` пропускать нельзя.** Prisma создаёт таблицы с выключенным RLS, а ключ
> `NEXT_PUBLIC_SUPABASE_ANON_KEY` по своей природе попадает в браузер. Пока RLS не
> включён, через него читается и переписывается вся база, включая хеши паролей.
> Команду повторяют после каждого `db:push` на новой базе: новые таблицы приходят
> без RLS. Раздел 1a в `docs/DEPLOY.md`.

Открыть <http://localhost:3000>. По умолчанию — казахская локаль: `/kk`.

## Ключевые проектные решения

**Источник истины по контингенту — АИС Platonus.** Платформа является источником
истины по учебному процессу в дистанционном формате и передаёт результаты обратно.
Весь код интеграции изолирован в `src/integration/platonus`; приложение работает
со своими моделями и не знает формата Platonus.

**Проверка объёма курса.** Публикация невозможна, если сумма плановых академических
часов всех элементов содержания не равна `кредиты × 30`. Величина расхождения
показывается преподавателю явно, кнопка публикации неактивна с объяснением причины.

**Разделение плановой трудоёмкости и фактической активности.** Плановые часы задаёт
преподаватель — они соотносятся с кредитами и проверяются контролирующими органами.
Фактическая активность (время, завершённые элементы) подтверждает участие и передаётся
в ИС МО в составе данных о посещаемости.

**Настройки, а не константы.** Коэффициенты формулы итоговой оценки, порог допуска,
число периодов рубежного контроля, продолжительность академического часа и параметры
учёта времени хранятся в таблице `system_settings` и правятся через `/admin/settings`.
Наследование: вуз → дисциплина → курс.

**Доступ по принадлежности к объекту.** Роль «Преподаватель» сама по себе не даёт
доступа ни к одному курсу — требуется назначение на дисциплину в конкретном
академическом периоде. Реализовано в `src/server/guards.ts`.

**Нормативные правила — проверяемые предикаты, а не текст инструкции.** Соответствие
плана ГОСО, обязательные дисциплины, объём кредитов в год, продолжительность
академического периода, условия диплома с отличием и допуска к аттестации живут
в `src/domain` отдельными функциями без обращения к базе. Поэтому они покрыты
тестами и одинаково работают и в интерфейсе, и на сервере: интерфейс показывает
предупреждение, сервер отказывает.

**Согласование не переписывает историю.** Ведомость, ИУП, протокол защиты и
приложение к диплому фиксируют состояние на момент утверждения. Пересчёт оценок
задним числом не меняет выданный документ; изменение проходит отдельной операцией
и пишется в журнал аудита.

## Что не реализовано (перенесено за рамки этапов 1—7)

Прокторинг, антиплагиат, форумы и обсуждения, вебинары, мобильное приложение,
интеграция с Platonus через API (готов адаптер, требуется доступ вендора),
SCORM и LTI, сертификаты, двухфакторная аутентификация, углублённая аналитика.

Живое обновление сообщений в чатах требует постоянного соединения, которого нет
на Vercel: понадобится отдельный сокет-сервер. Уведомления по почте и push
работают в приложении, но требуют почтового сервиса и ключей VAPID.

Задания с загрузкой файлов **включены в этап 1** согласно замечанию раздела 10 ТЗ.

## Ограничения перед промышленной эксплуатацией

1. **Персональные данные.** Данные граждан РК подлежат хранению на территории
   Республики Казахстан. Supabase размещает данные вне РК. Пилот допустим
   на обезличенных или тестовых данных; промышленная эксплуатация с реальным
   контингентом — только после переноса БД на инфраструктуру в РК.
2. **Тариф Vercel.** Бесплатный тариф Hobby запрещает коммерческое использование,
   включая проекты, приносящие выгоду оплачиваемому исполнителю. Для платформы,
   разрабатываемой на возмездной основе, требуется тариф Pro либо размещение
   на сервере вуза. Подробнее — `docs/DEPLOY.md`.
3. **Открытые вопросы раздела 14 ТЗ** — сведены в `docs/OPEN-QUESTIONS.md`.
   Значения по умолчанию соответствуют типовой практике и заменяются
   в `/admin/settings` без изменения кода.

# Пошаговый запуск: от архива до работающего сайта

Инструкция рассчитана на запуск **без установки чего-либо на компьютер**.
Всё делается в браузере: GitHub → Supabase → Vercel.

Время: 30–45 минут. Стоимость: 0 ₸ на бесплатных тарифах (см. предупреждение
о тарифе Vercel в шаге 0).

---

## Что получится в итоге

Работающий сайт по адресу вида `https://ваш-проект.vercel.app`:

- публичный каталог курсов, доступный без входа;
- кабинеты обучающегося, преподавателя, методиста, офиса регистратора и администратора;
- наполненный демонстрационный курс на 90 академических часов;
- 30 демонстрационных обучающихся, банк из 20 вопросов, два теста, задание;
- интерфейс на казахском, русском и английском.

---

## Шаг 0. Прочитайте до начала

Два ограничения, которые лучше узнать сейчас, а не после запуска.

**Тариф Vercel.** Бесплатный тариф Hobby запрещает коммерческое использование —
им считается любое развёртывание, приносящее выгоду в том числе оплачиваемому
исполнителю. Если платформа разрабатывается по договору, нужен тариф Pro
(20 USD в месяц) либо размещение на сервере вуза. Для проверки работоспособности
и демонстрации Hobby подойдёт.

**Персональные данные.** Supabase хранит данные во Франкфурте, а закон РК требует
хранения персональных данных граждан РК на территории Казахстана. Поэтому:
**на этом развёртывании работайте только с демонстрационными данными.** Для реального
контингента потребуется перенос базы на инфраструктуру в РК — код при этом не меняется,
меняются только строки подключения.

## Шаг 1. Создайте три учётные записи

Если каких-то нет — зарегистрируйтесь, это бесплатно и занимает пару минут.

| Сервис | Адрес | Зачем |
|---|---|---|
| GitHub | <https://github.com> | Хранение кода; Vercel берёт код отсюда |
| Supabase | <https://supabase.com> | База данных и хранилище файлов |
| Vercel | <https://vercel.com> | Размещение сайта |

**Совет:** зарегистрируйтесь в Supabase и Vercel **через GitHub** («Continue with
GitHub»). Это избавит от лишних шагов при подключении репозитория.

## Шаг 2. Загрузите код в GitHub

### 2.1. Распакуйте архив

Распакуйте `university-lms.zip` в любую папку на компьютере. Внутри должны быть
файлы `package.json`, `README.md` и папки `src`, `prisma`, `docs`.

### 2.2. Создайте репозиторий

1. Откройте <https://github.com/new>.
2. **Repository name** — например, `university-lms`.
3. Выберите **Private** (код содержит структуру системы вуза — публиковать
   его не обязательно).
4. **Не отмечайте** «Add a README file» — репозиторий должен быть пустым.
5. Нажмите **Create repository**.

### 2.3. Загрузите файлы

На странице пустого репозитория найдите ссылку **«uploading an existing file»**
(в тексте «…or push an existing repository from the command line»).

1. Откройте папку с распакованным архивом.
2. Выделите **всё содержимое** (Ctrl+A) — файлы и папки.
3. Перетащите их в окно браузера.

> **Важно.** Перетаскивайте именно содержимое папки, а не саму папку.
> В корне репозитория должен оказаться `package.json`, а не
> `university-lms/package.json`.

4. Дождитесь окончания загрузки (172 файла, около минуты).
5. Внизу страницы нажмите **Commit changes**.

### 2.4. Проверьте результат

На главной странице репозитория должны быть видны:

```
docs/  messages/  prisma/  public/  scripts/  src/  tests/
package.json  README.md  next.config.mjs  vercel.json  tsconfig.json
```

Если вместо этого видна одна папка — вы перетащили папку целиком.
Удалите репозиторий и повторите шаг 2.3.

## Шаг 3. Создайте базу данных в Supabase

### 3.1. Новый проект

1. Откройте <https://supabase.com/dashboard> → **New project**.
2. **Name** — `university-lms`.
3. **Database Password** — нажмите **Generate a password** и **сразу сохраните
   его** в надёжном месте. Позже посмотреть его будет нельзя.
4. **Region** — выберите **Central EU (Frankfurt)**. Это ближайший к Казахстану
   доступный регион, задержка около 80–110 мс. Другой регион добавит заметную
   задержку к каждому запросу.
5. Нажмите **Create new project**.

Проект создаётся 1–2 минуты. Дождитесь, пока индикатор наверху перестанет
показывать «Setting up project».

### 3.2. Строки подключения

Нужны **две разные строки** — приложение и создание схемы подключаются по-разному.

Обе находятся под кнопкой **Connect** — это зелёная кнопка **вверху страницы,
по центру**, справа от переключателя ветки `main`. Не ищите их в разделе
«Database → Settings»: там только настройки пула, которые менять не нужно.

Нажмите **Connect**. Откроется окно `Connect to your project`.

#### Быстрый путь: вкладка ORMs → Prisma

Если в окне есть вкладка **ORMs** — откройте её и выберите **Prisma**.

> **Сразу о главном: вводить оттуда ничего не нужно.**
> Supabase показывает инструкцию «как подключить Prisma с нуля», а в этом
> проекте всё уже настроено. Конкретно:
>
> | Что показывает Supabase | Нужно ли выполнять |
> |---|---|
> | `npx prisma init` | **Нет** — Prisma уже инициализирована |
> | Блок `datasource db { … }` для `prisma/schema.prisma` | **Нет** — он уже есть в проекте, слово в слово |
> | `npx skills add supabase/agent-skills` | **Нет** — это подсказки для ИИ-инструментов, к платформе отношения не имеют |
>
> Можете сверить: откройте `prisma/schema.prisma` в архиве — блок `datasource`
> совпадает с тем, что показывает Supabase. Это подтверждение, что проект
> настроен верно.

Из всего окна нужна **одна вкладка над блоком кода — `.env.local`**
(она соседняя с `prisma/schema.prisma`). Нажмите её. Там будут две строки:

```
DATABASE_URL="postgres://postgres.xxxxx:[YOUR-PASSWORD]@aws-0-eu-central-1.pooler.supabase.com:6543/postgres?pgbouncer=true"
DIRECT_URL="postgres://postgres.xxxxx:[YOUR-PASSWORD]@aws-0-eu-central-1.pooler.supabase.com:5432/postgres"
```

Что с ними сделать:

1. Скопируйте обе.
2. В каждой замените `[YOUR-PASSWORD]` — **вместе с квадратными скобками** —
   на пароль базы из шага 3.1.
3. В конец **первой** строки допишите `&connection_limit=1`.

Готовые значения сохраните в блокнот, они понадобятся на шаге 5.
Переходите к шагу 3.3.

#### Обычный путь

Если вкладки ORMs нет, в окне будет список вариантов подключения.
Возьмите **два из трёх**:

| Что взять в окне Connect | Порт | Переменная |
|---|---|---|
| **Transaction pooler** | 6543 | `DATABASE_URL` |
| **Session pooler** | 5432 | `DIRECT_URL` |
| ~~Direct connection~~ | 5432 | **не использовать** |

**Строка A — Transaction pooler → `DATABASE_URL`**

```
postgresql://postgres.abcdefghijklm:[YOUR-PASSWORD]@aws-0-eu-central-1.pooler.supabase.com:6543/postgres
```

Замените `[YOUR-PASSWORD]` на пароль из шага 3.1 и **допишите в конец**:

```
?pgbouncer=true&connection_limit=1
```

Готовая строка:

```
postgresql://postgres.abcdefghijklm:ВАШПАРОЛЬ@aws-0-eu-central-1.pooler.supabase.com:6543/postgres?pgbouncer=true&connection_limit=1
```

> Параметры в конце обязательны. Без них при одновременной работе многих
> студентов подключения к базе закончатся и сайт начнёт отдавать ошибки.

**Строка B — Session pooler → `DIRECT_URL`**

```
postgresql://postgres.abcdefghijklm:ВАШПАРОЛЬ@aws-0-eu-central-1.pooler.supabase.com:5432/postgres
```

Только замените пароль, ничего не дописывайте.

> **Почему не Direct connection.** Третий вариант в окне (`db.xxxxx.supabase.co`)
> работает только по IPv6 либо с платным IPv4-адресом, а Vercel подключается
> по IPv4 — сборка завершится ошибкой `Can't reach database server`.
> Session pooler лишён этого ограничения и при этом поддерживает подготовленные
> выражения, которые нужны Prisma для создания схемы.

Сохраните обе строки в блокнот — они понадобятся на шаге 5.

> **Как проверить себя.** У обеих строк хост оканчивается на
> **`pooler.supabase.com`**, различаются они только портом: `6543` у первой,
> `5432` у второй. Если в строке видите `db.abcdefghijklm.supabase.co` —
> это Direct connection, вернитесь и возьмите Session pooler.

### 3.3. Ключи API

1. **Project Settings** → **API**.
2. Скопируйте три значения:

| Что копировать | Куда пойдёт |
|---|---|
| **Project URL** (вида `https://abcdefghijklm.supabase.co`) | `NEXT_PUBLIC_SUPABASE_URL` |
| **anon public** (длинный ключ, начинается с `eyJ`) | `NEXT_PUBLIC_SUPABASE_ANON_KEY` |
| **service_role** (нажмите «Reveal», тоже начинается с `eyJ`) | `SUPABASE_SERVICE_ROLE_KEY` |

> `service_role` обходит все ограничения доступа к данным. Он используется
> только на сервере и никогда не попадает в браузер. Не публикуйте его
> и не переименовывайте переменную с префиксом `NEXT_PUBLIC_`.

### 3.4. Хранилище файлов

1. В левом меню: **Storage** → **New bucket**.
2. Создайте первый бакет:
   - **Name**: `materials`
   - **Public bucket**: **выключено** (это принципиально — учебные материалы
     не должны быть доступны по прямой ссылке)
   - **Create bucket**
3. Создайте второй бакет тем же способом:
   - **Name**: `submissions`
   - **Public bucket**: **выключено**

Должно получиться два приватных бакета. Все ссылки на файлы система выдаёт
подписанными, со сроком действия 15 минут, и только после проверки прав доступа.

## Шаг 4. Сгенерируйте секретные ключи

Нужны три случайные строки. Это просто набор случайных символов — их не нужно
нигде «создавать», ни с чем связывать и никуда регистрировать. Сгенерировали,
записали в блокнот, на шаге 5 вставили в переменные Vercel.

> **Не используйте раздел JWT-ключей Supabase.**
> В Supabase есть страница `JWT Keys` с кнопкой «Create standby key» —
> **она к этому шагу отношения не имеет.** Там управление ключами подписи
> токенов самого Supabase Auth, а платформа его не использует: у неё
> собственная аутентификация (Auth.js) со своей таблицей пользователей.
> Создание standby-ключа не даст нужного результата и без необходимости
> затрагивает настройки проекта.

### Как сгенерировать

Откройте **любую** страницу в браузере, нажмите **F12** → вкладка **Console**.
Вставьте целиком и нажмите Enter:

```js
const b64 = n => btoa(String.fromCharCode(...crypto.getRandomValues(new Uint8Array(n))));
const hex = n => [...crypto.getRandomValues(new Uint8Array(n))].map(b => b.toString(16).padStart(2, '0')).join('');
console.log('AUTH_SECRET=' + hex(32));
console.log('IIN_ENCRYPTION_KEY=' + b64(32));
console.log('CRON_SECRET=' + hex(32));
```

Выведет три готовые строки — скопируйте их в блокнот.

Если консоль браузера по каким-то причинам недоступна, подойдёт любой
онлайн-генератор случайных строк, например <https://generate-secret.vercel.app/32>
(обновите страницу трижды). Для `IIN_ENCRYPTION_KEY` в этом случае нужен
именно вариант в base64 — см. требование ниже.

### Что получилось

| Переменная | Формат | Назначение |
|---|---|---|
| `AUTH_SECRET` | 64 символа, hex | Подпись сессий пользователей |
| `IIN_ENCRYPTION_KEY` | **base64, ровно 32 байта** | Шифрование ИИН |
| `CRON_SECRET` | 64 символа, hex | Защита служебных маршрутов и первичной инициализации |

**Проверьте `IIN_ENCRYPTION_KEY`:** он должен выглядеть как строка примерно
из 44 символов, оканчивающаяся на `=`, например
`k9Tz+Qw3Rr8mN1pXvL6aH2sD5fG7jK0bC4eY8uI3oA=`. Если получилась строка
из одних цифр и букв a–f — это hex, он не подойдёт, шифрование не запустится
с ошибкой «должен быть 32 байта в base64».

> **`IIN_ENCRYPTION_KEY` восстановлению не подлежит.** Потеряете ключ —
> все зашифрованные ИИН станут нечитаемыми навсегда. Сохраните его отдельно,
> в надёжном месте вуза, до первого запуска.

## Шаг 5. Разверните на Vercel

### 5.1. Создайте проект

1. Откройте <https://vercel.com/new>.
2. В списке репозиториев найдите `university-lms` → **Import**.
   - Если репозитория нет — нажмите **Adjust GitHub App Permissions**
     и дайте Vercel доступ к нему.
3. **Framework Preset** определится как **Next.js** — оставьте.
4. **Root Directory** — оставьте `./`.
5. **Build Command**, **Output Directory**, **Install Command** — **не трогайте**.
   Они заданы в файле `vercel.json` внутри проекта.

### 5.2. Переменные окружения

Разверните блок **Environment Variables** и добавьте по очереди.
Для каждой: имя в поле **Key**, значение в **Value**, затем **Add**.

| Key | Value |
|---|---|
| `DATABASE_URL` | Строка A из шага 3.2 (порт 6543, с `?pgbouncer=true&connection_limit=1`) |
| `DIRECT_URL` | Строка B из шага 3.2 (порт 5432) |
| `NEXT_PUBLIC_SUPABASE_URL` | Project URL из шага 3.3 |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | anon public из шага 3.3 |
| `SUPABASE_SERVICE_ROLE_KEY` | service_role из шага 3.3 |
| `AUTH_SECRET` | Ключ из шага 4 |
| `IIN_ENCRYPTION_KEY` | Ключ из шага 4 (base64, 32 байта) |
| `CRON_SECRET` | Ключ из шага 4 |
| `AUTH_TRUST_HOST` | `true` |
| `SUPABASE_BUCKET_MATERIALS` | `materials` |
| `SUPABASE_BUCKET_SUBMISSIONS` | `submissions` |

Переменную `AUTH_URL` добавим на шаге 5.4 — сначала нужно узнать адрес сайта.

> **Проверьте перед сборкой:** в значениях нет пробелов по краям и кавычек.
> Вставляйте строки подключения целиком, вместе с `postgresql://`.

### 5.3. Запустите сборку

Нажмите **Deploy**.

Сборка занимает 3–5 минут. В журнале последовательно появятся:

```
Running "install" command: npm ci
Running "build" command: prisma generate && prisma db push --skip-generate && next build

✔ Generated Prisma Client
🚀  Your database is now in sync with your Prisma schema.
▲ Next.js 15.5.24
✓ Compiled successfully
✓ Generating static pages (82/82)
```

Строка **«Your database is now in sync with your Prisma schema»** означает,
что все 53 таблицы созданы в Supabase. Это и есть создание схемы —
отдельных действий не требуется.

При успехе появится страница **Congratulations** со ссылкой на сайт.

### 5.4. Добавьте адрес сайта

Адрес известен только после первой сборки — поэтому `AUTH_URL` добавляется
сейчас, а не вместе с остальными переменными.

**Возьмите правильный адрес.** Vercel выдаёт несколько, и они не равнозначны:

| Адрес | Брать? |
|---|---|
| `university-lms.vercel.app` | ✅ **Да** — постоянный, всегда указывает на текущую версию |
| `university-lms-a1b2c3d4.vercel.app` | ❌ Нет — привязан к одной сборке, после следующего деплоя устареет |

На экране «Congratulations» часто показан именно второй — с хвостом из
случайных символов. Постоянный адрес смотрите в **Settings → Domains**,
он первый в списке.

Формат значения:

```
✅ https://university-lms.vercel.app
❌ https://university-lms.vercel.app/      ← лишняя косая черта в конце
❌ university-lms.vercel.app               ← нет https://
❌ https://university-lms-a1b2c3d4.vercel.app  ← адрес одной сборки
```

Далее:

1. **Settings** → **Environment Variables** → **Add**:

| Key | Value |
|---|---|
| `AUTH_URL` | Постоянный адрес сайта в формате выше |

2. Вкладка **Deployments** → у верхнего развёртывания «⋯» → **Redeploy** → **Redeploy**.

> **На что влияет.** Вход в систему работает и без этой переменной: в проекте
> задано `trustHost: true`, и адрес определяется из заголовков запроса.
> `AUTH_URL` нужна для другого — из неё формируются `sitemap.xml`, `robots.txt`
> и метатеги Open Graph (требование F-P-06 ТЗ). Без неё карта сайта будет
> ссылаться на `localhost`, а ссылка на курс, отправленная в мессенджер,
> покажет неверное превью.

Если позже подключите домен вуза (**Settings → Domains**), обновите `AUTH_URL`
на него и снова сделайте Redeploy.

## Шаг 6. Заполните базу данных

Схема создана, но база пуста: нет ни ролей, ни шкалы оценивания, ни пользователей.
Заполним её одним запросом.

### 6.1. Проверьте связь с базой

Откройте новую вкладку и вставьте в адресную строку:

```
https://ВАШ-САЙТ.vercel.app/api/setup
```

Появится сообщение об ошибке `Неверный ключ доступа` — это правильно:
маршрут защищён. Проверить его из адресной строки нельзя, нужен заголовок.

### 6.2. Запустите инициализацию

Откройте **консоль браузера** на странице вашего сайта: **F12** → вкладка
**Console**. Вставьте команду, подставив свой `CRON_SECRET`:

```js
await fetch('/api/setup?demo=true', {
  method: 'POST',
  headers: { Authorization: 'Bearer ВСТАВЬТЕ_СЮДА_CRON_SECRET' }
}).then(r => r.json())
```

Нажмите Enter и подождите 10–30 секунд.

**Ожидаемый ответ:**

```json
{
  "ok": true,
  "log": [
    "Справочники загружены: роли, шкалы оценивания (Приложения 1 и 2), настройки системы.",
    "Бакеты объектного хранилища проверены.",
    "Демонстрационные данные загружены: факультет, 2 кафедры, 2 программы, 8 дисциплин, 3 преподавателя, 30 обучающихся, наполненный курс."
  ],
  "state": { "roles": 9, "users": 36, "courses": 5 },
  "credentials": {
    "password": "Demo2026!lms",
    "accounts": ["admin@demo.example.kz — администратор", "..."]
  }
}
```

> Консоль браузера должна быть открыта **на странице вашего сайта**, а не
> на пустой вкладке — иначе относительный путь `/api/setup` никуда не приведёт.

### 6.3. Если нужны только справочники, без демо-данных

Уберите параметр `demo=true` — загрузятся только роли, шкалы оценивания
и настройки системы. Дальше пользователей и дисциплины загружают импортом
из XLSX через админку.

```js
await fetch('/api/setup', {
  method: 'POST',
  headers: { Authorization: 'Bearer ВАШ_CRON_SECRET' }
}).then(r => r.json())
```

## Разбор ошибок

### Сборка на Vercel падает

**`Can't reach database server` или `P1001`**

Чаще всего в `DIRECT_URL` попал **Direct connection** вместо **Session pooler**.
Проверьте хост: должно быть `...pooler.supabase.com`, а не `db.xxxxx.supabase.co`.
Прямое подключение на бесплатном тарифе работает только по IPv6, которого
у Vercel нет.

Остальные причины:
- пароль подставлен вместо `[YOUR-PASSWORD]`, вместе со скобками;
- в пароле нет символов `@`, `:`, `/`, `?`, `#` — если есть, пересоздайте
  пароль в Supabase (**Settings → Database → Reset database password**),
  выбрав вариант без спецсимволов;
- проект Supabase создан и не находится в состоянии «Setting up».

**`prepared statement "s0" already exists` или ошибка при `db push`**

`DATABASE_URL` и `DIRECT_URL` перепутаны местами. Первая должна оканчиваться
на `6543/postgres?pgbouncer=true&connection_limit=1`, вторая — на `5432/postgres`.

**`Environment variable not found: DATABASE_URL`**

Переменная не добавлена либо добавлена не для того окружения. В Vercel при
добавлении должны быть отмечены все три галочки: Production, Preview, Development.

### Сайт открылся, но не работает

**Ошибка при открытии главной страницы**

База пуста — вы пропустили шаг 6. Выполните инициализацию.

**Не удаётся войти, страница перезагружается**

Проверьте `AUTH_SECRET` — она обязательна и должна быть задана для всех
окружений (Production, Preview, Development). Если переменная добавлялась
после сборки, нужен Redeploy: значения окружения подхватываются только
при развёртывании.

**Ссылки в мессенджерах ведут на `localhost`, sitemap.xml пустой**

Не задана `AUTH_URL` либо взят адрес конкретной сборки вместо постоянного.
Возьмите адрес из **Settings → Domains**, без косой черты в конце,
и сделайте Redeploy.

**`Неверный e-mail или пароль`**

Проверьте раскладку: пароль `Demo2026!lms` содержит восклицательный знак.
После пяти неудачных попыток вход блокируется на 15 минут — подождите.

**Ошибка при инициализации: `IIN_ENCRYPTION_KEY должен быть 32 байта в base64`**

Ключ не в том формате. Нужна строка base64 (около 44 символов, обычно
оканчивается на `=`), а не hex. Сгенерируйте заново функцией `b64(32)`
из шага 4. Если ключ уже использовался для загрузки данных — после замены
придётся перезалить демо-данные с параметром `?force=true`.

### Файлы

**При загрузке файла ошибка `Bucket not found`**

Бакеты не созданы или названы иначе. Вернитесь к шагу 3.4: имена должны быть
ровно `materials` и `submissions`, строчными буквами.

**Файл загрузился, но не открывается**

Проверьте, что бакеты созданы как **приватные** и что `SUPABASE_SERVICE_ROLE_KEY`
скопирован полностью — это длинная строка, легко обрезать при копировании.

### `Hobby accounts are limited to daily cron jobs`

Проект уже настроен под Hobby: в `vercel.json` одна ежедневная задача,
эта ошибка появиться не должна. Если всё же появилась — значит используется
старая версия `vercel.json`. Откройте файл в GitHub и приведите блок `crons`
к такому виду:

```json
"crons": [
  { "path": "/api/cron/daily", "schedule": "0 2 * * *" }
]
```

Ограничения тарифа Hobby: **не чаще раза в сутки** и **не более двух задач**.
Это лимит тарифа, одинаковый для всех бесплатных аккаунтов — регистрация
нового аккаунта ничего не изменит.

На работу платформы суточное расписание не влияет: очередь интеграции с Platonus
на пилоте не используется, а повисшие сессии учёта времени закрываются и без
расписания — при следующем открытии материала обучающимся.

## Что дальше

### Загрузить реальные данные вуза

1. Войдите администратором → **Справочники** — сначала нужны факультеты,
   кафедры, программы и дисциплины. На пилоте их удобнее внести напрямую
   в Supabase (**Table Editor**) либо запросить у разработчика скрипт импорта.
2. **Пользователи** → **Шаблон XLSX** — скачайте, заполните, загрузите
   кнопкой **Импорт пользователей**. Система создаст учётные записи
   и выдаст файл с временными паролями — раздайте их по защищённому каналу.
3. **Академические периоды** → создайте текущий период и отметьте его текущим.
4. **Регистрация на курсы** → создайте курсы и зарегистрируйте группы.

### Настроить под академическую политику вуза

**Настройки** → приведите в соответствие с утверждённой политикой:
коэффициенты формулы итоговой оценки, порог допуска, число периодов рубежного
контроля, продолжительность академического часа.

Эти значения меняются без правки кода. Полный перечень открытых вопросов,
которые нужно уточнить у вуза, — в `docs/OPEN-QUESTIONS.md`.

### Перейти к промышленной эксплуатации

Перед работой с реальным контингентом обязательны:

1. Перенос базы данных на инфраструктуру в РК.
2. Переход с `prisma db push` на полноценные миграции — см. ниже.
3. Проверенная процедура восстановления резервной копии.
4. Тариф, допускающий коммерческое использование.

Подробности — `docs/DEPLOY.md`.

### Переход на миграции

Сейчас схема создаётся командой `prisma db push`: она приводит базу
в соответствие со схемой, но не ведёт историю изменений. Для пилота этого
достаточно, для промышленной эксплуатации — нет: без истории нельзя
откатить неудачное изменение и нельзя воспроизвести состояние базы.

Когда появится возможность работать локально:

```bash
npx prisma migrate dev --name init
git add prisma/migrations && git commit -m "init migration" && git push
```

Затем в `vercel.json` замените `prisma db push --skip-generate`
на `prisma migrate deploy`.

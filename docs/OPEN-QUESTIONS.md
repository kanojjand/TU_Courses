чтобы отсутствие ответа не блокировало разработку.

## 14.2. Вопросы, требующие решения

### 1. Академический час — 50 или 60 минут?

**Влияет на:** все расчёты трудоёмкости, пересчёт минут работы в академические часы.

**Решение в системе:** значение хранится в настройке `academic_hour_minutes`
(по умолчанию 50) и не зашито в код. Изменение в `/admin/settings` немедленно
меняет расчёты во всей системе.

**Важно:** менять значение после начала учебного периода не следует — это
изменит уже засчитанные объёмы освоенного времени. Решение нужно принять
до наполнения курсов.

### 2. Норматив соотношения контактных часов, СРОП и СРО

**Решение в системе:** модель `WorkTypeNorm` задаёт доли по видам работы
для каждой дисциплины, флаг `enforce_work_type_norms` включает контроль.
При включении курс, нарушающий норматив, не публикуется — с указанием
фактической и нормативной доли.

**Сейчас:** контроль выключен, соотношение остаётся на усмотрение преподавателя.

### 3. Только дистанционная форма или также очная?

**Влияет на:** необходимость учёта аудиторных занятий, интеграции с расписанием.

**Решение в системе:** `StudentProfile.studyForm` поддерживает очную, заочную,
дистанционную и вечернюю формы. Расписание аудиторных занятий в границы
системы не входит (раздел 1.2 ТЗ) — при поддержке очной формы контактные
часы всё равно планируются в конструкторе курса как элементы содержания.

### 4. Внешние слушатели

**Влияет на:** оплату, выдачу документов, открытую регистрацию.

**Сейчас:** не поддерживается. Саморегистрация отключена, учётные записи
создаёт администратор. Отнесено к этапу 4 «Масштабирование».

### 5. Идентификация обучающегося на аттестации

**Зависит от:** ответа по вопросу 14.1.1 — актуальной редакции Приказа № 137.

**Сейчас:** при прохождении теста фиксируются IP-адрес и user-agent попытки —
это базовый уровень контроля. Прокторинг (роль `PROCTOR` в модели уже
предусмотрена) отнесён к этапу 3.

**От ответа зависит срок внедрения прокторинга** — если норма требует
видеонаблюдения на промежуточной аттестации, этап 3 становится обязательным
до первой сессии.

### 6. Шкала Приложения 2 с уровнями ОЕК — применять на этапе 1?

**Решение в системе:** реализована. Профиль оценивания назначается дисциплине
через `Discipline.gradingProfile = LANGUAGE`. Справочник шкалы с привязкой
к уровням A1–C2 загружается сидом.

В демо-наборе профиль назначен дисциплине «Профессионально ориентированный
иностранный язык» (LAN1102).

**Требует подтверждения:** соответствие процентных диапазонов уровням ОЕК.
Текущее соответствие задано в `src/domain/grading.ts` → `cefrForPercent`
и подлежит сверке с Приложением 2 после получения актуальной редакции.

### 7. Интегрированный социальный GPA — утверждена ли методика?

**Решение в системе:** функция `calculateSocialGpa` реализует настраиваемую
линейную модель: академический GPA с весом плюс взвешенные компоненты
(научная, общественная, спортивная активность).

Расчёт **выключен** настройкой `social_gpa_enabled` до утверждения методики вузом.
Поле `GpaRecord.socialGpa` в модели предусмотрено.

### 8. Сроки хранения данных отчисленных

**Решение в системе:** настройка `retention_years_expelled` (по умолчанию 5 лет).

**Не реализовано:** автоматическое обезличивание по истечении срока.
Отнесено к этапу 2 — до утверждения срока реализовывать процедуру
безвозвратного изменения данных преждевременно.

### 9. Обязательна ли проверка курса методистом перед публикацией?

**Решение в системе:** настройка `course_require_methodist_review`
(по умолчанию **включено**).

При включении курс проходит цикл: черновик → на согласовании → согласован →
опубликован. Методист видит структуру ЭУМКД, силлабус и результат проверки
объёма часов, и может вернуть курс на доработку с комментарием.

При выключении преподаватель публикует курс самостоятельно — проверка
соответствия часов кредитам выполняется в обоих случаях.

### 10. Требуется ли запрет скачивания материалов?

**Решение в системе:** флаг `Course.preventDownload`, по умолчанию **включён**.

При включении: PDF открывается во встроенном просмотрщике с отключённой
панелью инструментов, ссылка на скачивание не показывается.

**Оговорка, которую следует довести до вуза.** Полный запрет сохранения
файла технически недостижим: содержимое всё равно попадает в браузер
пользователя. Реализованная мера — организационная, а не техническая:
она делает сохранение неочевидным, но не невозможным. Материалы, утечка
которых недопустима, размещать на платформе не следует.

## Что происходит при изменении ответов

Проектное решение состояло в том, чтобы ответы на открытые вопросы меняли
**настройки, а не код**. Ниже — что потребуется при получении ответов.

| Ответ получен | Действие | Требуется разработка |
|---|---|---|
| Академический час 60 минут | Изменить настройку | Нет |
| Другие коэффициенты формулы | Изменить настройки | Нет |
| Один период рубежного контроля | Изменить настройку | Нет |
| Норматив по видам работы | Заполнить `WorkTypeNorm`, включить контроль | Нет |
| Согласование методистом не требуется | Выключить настройку | Нет |
| Скачивание разрешить | Снять флаг у курсов | Нет |
| Брендбук вуза | Правка CSS-переменных в `globals.css` | Минимальная |
| Форма ведомости вуза | Правка `exportGradeSheet` | Локальная, один файл |
| Шаблон силлабуса вуза | Правка состава полей `SyllabusForm` и модели `Syllabus` | Локальная |
| Документация API Platonus | Правка `src/integration/platonus/client.ts` | Локальная, один файл |
| Методика социального GPA | Настройка компонентов и весов | Небольшая |
| Требования прокторинга | Отдельный этап | Этап 3 |

## Приоритет запросов

**Направить немедленно, на первой неделе:**

1. Официальное письмо в ТОО «Платонус» (п. 14.1.10) — согласование занимает
   несколько недель и является критическим фактором для этапа 2.
2. Запрос актуальной редакции Приказа № 137 (п. 14.1.1) — от него зависит
   объём работ по прокторингу.
3. Запрос академической политики (п. 14.1.2) — без неё расчёт итоговых оценок
   ведётся по значениям, которые могут не совпадать с принятыми в вузе.

**До наполнения курсов реальным содержанием:**

4. Решение по академическому часу (14.2.1) — изменение после начала периода
   исказит уже засчитанные объёмы.
5. Перечень дисциплин с объёмами в кредитах (п. 14.1.4).

**До начала работы с реальным контингентом:**

6. Решение по размещению инфраструктуры в РК (п. 14.1.3).
7. Утверждённая форма согласия на обработку ПДн (п. 14.1.11).
